### Фаза 2 — logger (задача #7, вынесен вперёд)
- `apps/web/lib/logger.ts`: pino v10 + pino-pretty (только локально, на Vercel чистый JSON stdout).
- Redact-пути: headers `authorization`/`cookie`/`x-telegram-bot-api-secret-token`, generic `*.password/*.token/*.apiKey/*.secret`, точечные для всех env-токенов (`SUPABASE_SERVICE_ROLE_KEY`, `ANTHROPIC_API_KEY`, `TELEGRAM_BOT_TOKEN`, `YOOKASSA_SECRET_KEY`, `CRYPTOBOT_TOKEN`, `SENTRY_AUTH_TOKEN`, `UPSTASH_REDIS_REST_TOKEN`), PII денилист из `docs/observability.md` (`*.content/*.text/*.email/*.phone/*.card`).

**Зачем logger перед env:** чтобы все последующие модули писали сразу через `logger.*`, а не через `console.*` с последующей переделкой.

- Три Supabase-клиента:
  - `browser.ts` — `@supabase/ssr.createBrowserClient`, singleton, только `NEXT_PUBLIC_*`.
  - `server.ts` — `createServerClient` с `cookies()` из `next/headers`, try/catch no-op для RSC read-only cookies.
  - `admin.ts` — `@supabase/supabase-js.createClient` с `service_role`, `import 'server-only'` первой строкой, `autoRefreshToken:false, persistSession:false`.

### Фаза 4 — Sentry baseline (задачи #5, #6)
- `apps/web/lib/sentry.ts`:
  - `beforeSend` с рекурсивным `scrubPii` (depth-limit 6).
  - Денилист ключей: `/^(content|message|text|email|phone|card|password|token)$/i`.
  - Чистит `event.request.{data, query_string, headers}`, `breadcrumbs.{data, message}` (regex на `Bearer\s+…`), `event.extra`.
  - `sharedOptions` с `environment = VERCEL_ENV ?? NODE_ENV`, `tracesSampleRate = 0.1` в prod.
- 3 runtime config'а: `sentry.{client, server, edge}.config.ts` с `if (dsn) Sentry.init(...)` — dormant без DSN.
- `instrumentation.ts` — через `NEXT_RUNTIME` грузит нужный config + fail-fast `getServerEnv()` на старте Node-процесса (skip во время `phase-production-build`).
- `instrumentation-client.ts` — `onRouterTransitionStart = Sentry.captureRouterTransitionStart` (требует Next 16).
- `next.config.ts` обёрнут в `withSentryConfig({silent: !CI, widenClientFileUpload, sourcemaps: {disable: !hasSentryAuth}})`.

## Ключевые решения и trade-off'ы

### 1. Lazy Proxy-getter для env
**Альтернатива:** парсить env на import (`const env = schema.parse(process.env)` в topleveln-scope).
**Почему отказались:** это ломает `next build` в CI без `.env.local`. Build падает на import-time evaluation до того, как у него будет шанс залогировать понятную ошибку.
**Выбор:** `getServerEnv()` с кэшем + Proxy-обёртка. Парсинг при первом обращении, fail-fast через `instrumentation.ts` на runtime старте (но НЕ на build). В итоге build всегда собирается, а приложение падает только если реально стартует без env.

### 2. `import 'server-only'` вместо соглашения
**Альтернатива:** договориться, что `admin.ts` не импортируется из client-кода, и надеяться на ревью.
**Почему отказались:** service_role ключ обходит RLS. Утечка в клиент-бандл = компрометация БД.
**Выбор:** `server-only` первой строкой в `admin.ts` и `env.server.ts` — бандлер упадёт с ошибкой при попытке импорта, не давая такой ошибке доехать до prod.

### 3. Три Supabase-клиента вместо одного
**Альтернатива:** один клиент с if'ами по `typeof window`.
**Почему отказались:** разная логика cookies (browser vs server-with-next-headers vs server-without-cookies), разные ключи (anon vs service_role), разные гарантии (client/server safe vs server-only).
**Выбор:** три файла с явными ответственностями. `browser.ts` — ни при каких условиях не попадает service_role. `admin.ts` — ни при каких условиях не попадает в клиент. Файловая граница + `server-only` директива.

### 4. Logger перед env в порядке задач
**Альтернатива:** сначала env, потом logger.
**Почему отказались:** если logger внедряется после env — весь env.ts уже написан с `console.*`, потом переделывать. Плюс при падении env хочется залогировать через настоящий logger.
**Выбор:** logger первой реальной задачей фазы 2. Правда, в `env.ts` всё равно остался `console.error` (pre-logger fallback — если env валится, логгер может не успеть подняться). Это acceptable, добавлю комментарий в коде.

### 5. Sentry PII-scrubber — рекурсивный + header denylist
**Альтернатива:** стандартные Sentry defaults (`sendDefaultPii: false`).
**Почему отказались:** дефолт не защищает от пользовательских полей вроде `message`, `content`, `text` — а у нас именно там будет чат с клиентом и суммы заказов. Ещё дефолт не трогает breadcrumbs, где Bearer-токены могут проскочить через fetch-crumbs.
**Выбор:** явный `beforeSend` с рекурсивной чисткой по денилисту + регэксп на Bearer в crumb.message. Depth-limit 6 — защита от циклов. Если в ревью найдут пропущенное поле — легко расширить PII_KEY_RE.

### 6. Merge-стратегия
**План:** squash-merge.
**Фактически:** обычный Merge commit (default кнопка в GitHub UI).
**Последствия:** на main 6 коммитов вместо 1 (5 feature + 1 merge). История длиннее, но не неверная.
**На будущее:** в Settings → Pull Requests выключить Merge commit, оставить Squash + Rebase.

## Проблемы и решения

### Проблема #1 (high) — `.env.example` drift + near-miss secret leak

При `/aif-verify` нашли 9 env-переменных, которые код использует, но в шаблоне их нет. Пока пытался починить, **реальные** Supabase-ключи (DATABASE_URL password, ANON_KEY, SERVICE_ROLE_KEY) оказались в `.env.example` — файле, который tracked git'ом и специально создан как «место для env-значений». `git add -A` + `commit` опубликовал бы их.

**Ошибка не закоммичена** (файл был modified, не staged). Пользователь вынес секреты в gitignored `.env` до того, как я успел сделать commit, template очищен до placeholders-only.

**Patch:** [`2026-04-22-22.44.md`](../patches/2026-04-22-22.44.md). Prevention: CI-скрипт для schema↔template sync (Sprint 2), мысленная модель «`.env.example` — public artifact, реальные значения только в `.env.local`».

### Проблема #2 (не блокировала Sprint 1) — Sentry build options

`hideSourceMaps` и `disableLogger` — deprecated в `@sentry/nextjs` v10. Заменено на `sourcemaps: {disable: !hasSentryAuth}` + убран `disableLogger`. Build зелёный.

### Проблема #3 (не блокировала Sprint 1) — `typedRoutes` вне experimental

В Next 16 `typedRoutes` переехал из `experimental` в top-level config. Починено.
