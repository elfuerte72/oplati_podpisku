## Проблема: Zod `.optional()` падает на пустых строках

### Как проявилось

```
Invalid server env:
  - ANTHROPIC_API_KEY: Required
  - TELEGRAM_BOT_TOKEN: String must contain at least 1 character(s)
  - TELEGRAM_WEBHOOK_SECRET: String must contain at least 1 character(s)
  - TELEGRAM_OPERATORS_GROUP_ID: String must contain at least 1 character(s)
  - YOOKASSA_SHOP_ID: String must contain at least 1 character(s)
  - YOOKASSA_SECRET_KEY: String must contain at least 1 character(s)
  - YOOKASSA_WEBHOOK_SECRET: String must contain at least 1 character(s)
  - CRYPTOBOT_TOKEN: String must contain at least 1 character(s)
  - CRYPTOBOT_WEBHOOK_SECRET: String must contain at least 1 character(s)
  - UPSTASH_REDIS_REST_URL: Invalid url
  - UPSTASH_REDIS_REST_TOKEN: String must contain at least 1 character(s)
  - TRIGGER_API_KEY: String must contain at least 1 character(s)
  - SENTRY_DSN: Invalid url
```

### Root cause

В `.env.local` (скопирован из `.env.example`) все опциональные ключи имели форму `KEY=` — пустая строка как placeholder «ещё не заполнил».

Zod `.optional()` интерпретирует только `undefined` как «отсутствует». Пустая строка — это валидный `string`, который:
- проходит `z.string()`,
- падает на `.min(1)` / `.url()`.

Итог: fail-fast срабатывает там, где не должен — все опциональные Sprint 1.5+ ключи «обязательны», потому что `""` ≠ `undefined`.

Отдельно: `ANTHROPIC_API_KEY` был объявлен как `z.string().min(1)` без `.optional()`. Sprint 1 не использует AI — значит, это лишняя жёсткая зависимость. Нужно было с самого начала сделать его `.optional()`.

### Fix

В `apps/web/lib/env.ts` введён helper:

```typescript
function optionalEnvString(inner: z.ZodTypeAny = z.string().min(1)): z.ZodType {
  return z.preprocess((v) => (v === '' ? undefined : v), inner.optional());
}
const optionalUrl = () => optionalEnvString(z.string().url());
```

Применён ко всем Sprint 1.5+ ключам:
- `TELEGRAM_*` (3 ключа),
- `YOOKASSA_*` (3 ключа),
- `CRYPTOBOT_*` (2 ключа),
- `UPSTASH_*` (2 ключа),
- `TRIGGER_API_KEY`,
- `SENTRY_*` (2 ключа),
- `DATABASE_URL`, `DATABASE_URL_DIRECT`,
- `NEXT_PUBLIC_SENTRY_DSN`, `NEXT_PUBLIC_APP_URL`.

`ANTHROPIC_API_KEY` переведён из required в `optionalEnvString()` до Sprint 1.5.

### Проверка

`pnpm --filter web dev` — стартует чисто, API `/api/health` отвечает `{"ok":true}`, страница рендерится.

### Патч

`.ai-factory/patches/2026-04-23-00.00.md` — полный post-mortem с 6 правилами профилактики:

1. **Всегда preprocess `"" → undefined`** для опциональных env-string.
2. **Единый хелпер `optionalEnvString`** — не размножать preprocess вручную.
3. **Не плодить «обязательные» ключи, которые используются через N спринтов** — это фальшивый fail-fast.
4. **Тестировать env-схему с пустыми значениями** — не только с валидными.
5. **`.env.example` — это placeholder'ы, не данные** — пустая строка в dev-окружении должна трактоваться как «отсутствует».
6. **`instrumentation.ts` fail-fast — хорошо, но только если схема корректна** — иначе это self-inflicted deployment block.

Теги: `#env #zod #validation #dx #fail-fast #schema-drift #nextjs`

## Merge

Пользователь нажал «Merge» в GitHub UI.

**Ожидалось:** Squash and merge (1 commit в main).
**Фактически:** обычный Merge commit `5d783dd` — все 5 feature-коммитов + merge-commit попали в историю main.

Разница:
- **Squash:** `feat(web): Next.js 16 baseline + observability` — один коммит, чистая линейная история, теряется bisect-гранулярность внутри PR.
- **Merge commit:** сохраняет все 5 коммитов + merge; история не линейная, но bisect работает на каждый из 5 этапов.
- **Rebase:** 5 коммитов линейно без merge-commit'а.

Для solo-dev + маленьких PR (<10 файлов) разница косметическая. Для крупных PR я бы жёстче настоял на squash — merge commits быстро загрязняют `git log --oneline main`.

**Рекомендация (не действие):** в GitHub → Settings → General → Pull Requests выключить «Allow merge commits», оставить только «Allow squash merging» + «Allow rebase merging». Это force-исправит будущие deviations на уровне UI.
