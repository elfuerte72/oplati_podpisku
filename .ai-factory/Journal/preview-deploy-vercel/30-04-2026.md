# 2026-04-30 — Preview-деплой (Vercel fra1) — end-to-end smoke

Реализован milestone «Preview-деплой (Vercel fra1)» из `.ai-factory/ROADMAP.md`. End-to-end smoke: `/start` + текстовое сообщение к `@dev_test_podpiska_bot` на preview-деплое → запись в Supabase (`users` / `conversations` / `messages`).

## Решения (краткое зеркало плана)

- Repository-функции принимают `db` явно как параметр + опциональный pino-совместимый `RepoLogger` (см. `packages/db/src/repositories/logger.ts`). Это держит границу `@oplati/db` без зависимости от pino и облегчит мокирование в Sprint 2 vitest'ах.
- `users` upsert — через raw SQL (`db.execute(sql\`...\`)`), потому что partial unique index `WHERE telegram_id IS NOT NULL` в Drizzle 0.45 на `onConflictDoUpdate` требует ручного `targetWhere`-протокола; raw SQL детерминированнее и совместим с `prepare=false` (Supabase pooler).
- `(xmax = 0) AS created` в `RETURNING` — Postgres-трюк отличить INSERT от UPDATE.
- `display_name = COALESCE(EXCLUDED.display_name, users.display_name)` — Telegram-апдейт без `first_name` (anonymous, deep-link bot start) не перезатирает уже сохранённое имя.
- Запись в БД — синхронная до возврата 200 OK; ошибки БД глотаются (Sentry + log), AI-ответ всё равно уходит. Это явное graceful degradation — webhook не молчит при падении Postgres.
- AI-history НЕ загружается из БД на этом milestone — изолируем риск; подключим в milestone «State machine + AI tools».
- `preferredRegion='fra1'` + `maxDuration` (`/api/bot` 30s, `/api/health` 5s) — выровняли API routes с `docs/deployment.md`.

## Уроки сессии (для следующих preview-проверок)

1. **`Sensitive`-флаг в Vercel env скрывает значение от `vercel env pull`**, отдавая пустую строку — это by design. Локальный pull нельзя использовать для контроля «что сейчас в env runtime»; полагаемся на UI «Updated just now» и ручную сверку через rebuild.
2. **Vercel env применяется только к новым deployments.** Если поменяли `TELEGRAM_WEBHOOK_SECRET` после build'а — старый preview сохраняет старый/пустой секрет и отвечает 401. Лекарство: `vercel redeploy <url>` или новый push.
3. **Redeploy через Dashboard может выбрать deployment не из feature-ветки.** Проверять `vercel inspect <url>` → `Aliases` (должен быть `git-<branch>`, не `git-main`) — иначе тестируется не тот код.
4. **Telegram возвращает `404 Not Found` на `/bot/setWebhook`** при пустом токене — путь буквально становится `/bot/setWebhook`. Полезный сигнал: «токен пустой», а не «бот не существует».
5. **Vercel CLI v50 `vercel logs <url>` без `--follow` — это live-stream от текущего момента.** Историю логов CLI не отдаёт; для диагностики нужно либо открыть стрим до запроса, либо ловить через Dashboard.
