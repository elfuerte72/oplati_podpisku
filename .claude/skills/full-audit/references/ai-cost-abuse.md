# Ось H — AI-контур: защита расходов, инъекции, деградация

Оба канала (бот и веб-чат) идут через один `runAgent()` из `@oplati/agent`.
Слои защиты описаны в CLAUDE.md («Защита AI-расходов») и
`docs/reference/ai-cost-protection.md`. Проверяется: каждый слой на месте,
порядок слоёв правильный, fail-open/fail-closed соответствует задокументированному
решению.

## H1 · Порядок обороны (нарушение порядка = дыра)

1. **Rate-limit ДО всего**: `/api/chat` по IP, `/api/bot` по `telegram_id` —
   ДО роутера, ДО создания сессии, ДО записей в БД. Fail-open только при
   незаданном Upstash (осознанно); выключатель `RATE_LIMIT_DISABLED=1`.
2. **Haiku-роутер** (`packages/agent/src/router.ts`): приветствие/оффтоп/
   инъекция → каннед-ответ без Sonnet. При сомнении И при ошибке роутера —
   fail-open в агента (осознанно). Выключатель `AI_ROUTER_DISABLED=1`.
3. **Дневной глобальный токен-бюджет** (`ai_usage_daily` +
   `apps/web/lib/ai/budget.ts`, env `AI_DAILY_TOKEN_BUDGET`): взвешенные
   токены, fail-open при недоступной БД (осознанно), Sentry-алерт на пороге.
4. **Серверные границы tools** — см. H2.

## H2 · Границы `propose_order` (сервер не верит агенту)

- Диапазон $1–500; исключение — «пополнения» строго по slug из
  `HIGH_VALUE_SERVICE_SLUGS` до **$1200**; custom-описания всегда $500.
- ≤10 заказов/сутки на пользователя.
- Значение $1200 продублировано в `lib/telegram/amount.ts`,
  `StartScreen.tsx`, `CatalogView.tsx` — сверить синхронность всех точек.
- Клиентская цена НИКОГДА не принимается на веру: расчёт только серверный
  (`lib/pricing.ts`, `lib/catalog/build.ts`, `propose-order.ts` — одна функция
  округления `roundUpToWholeRubles` в обеих точках).
- Битая `pricing_policy` → `service_unavailable`, не «поверить клиенту».

## H3 · Prompt injection и вредный ввод

- Входы ВСЕХ tools — через Zod-схемы (`packages/agent` tool-схемы), сервер
  перепроверяет диапазоны независимо от агента.
- `web_search` возвращает недоверенный текст в контекст агента — денежные
  решения (сумма, сервис) обязаны проходить серверные границы H2, а не
  «то, что нашёл поиск».
- `confirm_order` — гейт `telegram_link_required` для веб-пользователя без
  `telegram_id`; платёжная ссылка не выдаётся в обход.
- Каннед-ответы роутера на инъекции — проверить, что новые user-facing пути
  не обходят роутер.

## H4 · История диалога

- Конвертация истории — ОБЩИЙ `toAgentHistory` (`lib/chat/history.ts`), дублей
  быть не должно. Он отрезает ведущие `assistant`: окно
  `loadRecentMessages(…, 20)` режет по числу строк, непарная запись → первый
  элемент `assistant` → Messages API 400 на каждый ход НАВСЕГДА (регресс H-1).
  Любой новый код загрузки истории обязан идти через него.
- Диалог пишется синхронно с graceful degradation: БД лежит → бот отвечает,
  но «забывает» (не 500).

## H5 · Флаги каналов

- `BOT_AI_ENABLED` (дефолт ВЫКЛ): бот молчит на текст/медиа/каталожные
  callback'и; работают только `/start`, `/support`, inline-меню. Выключенный
  путь не должен звать Anthropic вообще.
- `WEB_AI_ENABLED` (дефолт ВЫКЛ): любой текст в веб-чате → мгновенная статичная
  заготовка БЕЗ вызова Anthropic, БЕЗ сессии, БЕЗ записей в БД, БЕЗ rate-limit.
- Код обоих AI-путей цел (флаги — выключатели, не удаление); случайное
  включение пути мимо флага — находка.

## H6 · Деградация и модель

- Anthropic упал/таймаут → понятный ответ пользователю, не 500, не молчание.
- Default-модель `claude-sonnet-4-6`, override через `ANTHROPIC_MODEL`
  (dev/preview — Haiku). Захардкоженная модель мимо env — находка.
- `runAgentNoTools` и tool-loop: лимит итераций цикла (агент не может крутить
  tools бесконечно за наш счёт).
