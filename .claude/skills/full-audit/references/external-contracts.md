# Ось F — Внешние API-контракты

Контракты провайдеров подтверждены живыми вызовами и зафиксированы в CLAUDE.md
и `docs/reference/`. Проверяется: код соответствует ПОДТВЕРЖДЁННОМУ контракту,
а не доке провайдера (дока врёт — проверено многократно). Любой «додуманный»
контракт — находка.

## F1 · PaySpace (`apps/web/lib/pay-space/`)

- `createCard` — единственная мутирующая операция БЕЗ идемпотентного
  `request_id` у провайдера → **никогда не ретраится** (`idempotent: false`).
  Проверить, что ни один путь (включая recovery в `poll-payment`) не повторяет
  её без атомарного claim'а заказа: повтор = вторая профинансированная
  карта-призрак.
- `topup`/`withdraw`/`release` идемпотентны через `request_id` — формат
  короткий (`t_<16hex>`): длинный request_id (79 символов) уже давал silent
  `topup_failed` (инцидент 2026-06-26).
- Суммы приходят то строкой, то числом (`paySpaceMoney`); `exp_date` — `MM/YY`
  (НЕ `YYYY-MM-DD`); опц. поля `card`/`info` бывают `null`. Всё через Zod,
  дрейф → `PaySpaceContractError`, не молчание.
- `PaySpaceContractError.rawBody` — **неперечисляемое** свойство (тело может
  содержать полный PAN+CVV); `logger.ts` дополнительно redact'ит
  `err.rawBody`/`*.rawBody`. Проверить, что новых путей сериализации ошибки нет.
- async-`topup` поллится через `topup/check`; заказ завершается ТОЛЬКО при
  `status=completed`, иначе → `failed`.

## F2 · Love&Pay (`apps/web/lib/loveandpay/`)

- Base URL строго `https://api.prod.loveandpay.io/api/v2` — «голый» хост без
  `/api/v2` ломает И адрес, И HMAC-подпись (`signPath` подписывает путь из URL).
- ⚠️ Поле `amount` в теле вебхука неоднозначно: в `invoice.created` — копейки,
  в остальных событиях — рубли. Сверка оплаты — ТОЛЬКО по `amountKopecks` из
  нормализующей схемы (`amountRub` → копейки; `amount * 100` — лишь fallback
  для легаси/тестовой панели/polling). Любой новый код, читающий `amount`
  напрямую, — BLOCKER.
- Реальный контракт событий — `invoice.paid`, `data.id` (снят живым вызовом);
  тестовая панель кабинета шлёт фейковый формат — код не должен на неё
  ориентироваться.
- Лимиты API: 100 запросов/мин, 1 000/час — проверить, что ретраи/поллинг не
  могут их выесть.

## F3 · Freekassa (`apps/web/lib/freekassa/`)

- Подпись запроса — HMAC-SHA256 по отсортированным значениям через `|`;
  подпись уведомления — `MD5(MERCHANT_ID:AMOUNT:секрет2:MERCHANT_ORDER_ID)`.
- `nonce` — последовательность Postgres `freekassa_nonce` (миграция 0026), НЕ
  `Date.now()`: два конкурентных запроса в одну миллисекунду дали бы дубль.
- `createOrder` НЕ ретраится (мутирующая, без идемпотентного ключа, растущий
  nonce).
- `AMOUNT` уведомления разбирается точно в копейки БЕЗ `parseFloat`;
  `payer_account` (возможный полный PAN) в БД и логи — только маской.
- Контракт (живой платёж 2026-07-28): `intid` = `orderId` из `/orders/create`;
  `AMOUNT` = сумма НАШЕГО счёта без комиссии покупателя. Уведомление приходит
  ТОЛЬКО об успехе → неуспех виден только через поллинг (статусы: 1 оплачен /
  8 ошибка / 9 отмена / 6 возврат; неизвестный код НЕ терминален).
- Ответ вебхука — HTTP 200 всегда, но «принято» = тело `YES`; не-`YES`
  отдаётся только там, где повтор уведомления поможет.

## F4 · Rapira (`apps/web/lib/rapira/`)

- Публичный `GET /open/market/rates`, пара `USDT/RUB`, поле **`askPrice`**
  (не bid, не mid). Zod-контракт; ошибка сети/HTTP/контракта →
  `RATE_FALLBACK_USDT_RUB` (дефолт 81), не падение и не нулевой курс.

## F5 · Remnawave (`apps/web/lib/remnawave/`)

- Bearer `REMNAWAVE_API_TOKEN` — только server-side; timeout 10s; без ретраев.
- `by-telegram-id`: «нет юзера» = 200 + пустой массив, НЕ 404.
- `revoke` меняет ссылку, но НЕ продлевает `expireAt` (иначе кнопка = бесплатное
  продление). Хранить `response.uuid`, НЕ `vlessUuid`.
- Сбой панели/БД/отсутствие токена → понятный текст пользователю, не молчание.

## F6 · Telegram Bot API (`apps/web/lib/telegram/`)

- `/api/bot`: проверка `X-Telegram-Bot-Api-Secret-Token`; `401` — единственный
  non-200 кейс.
- Исходящий HTML экранируется (`buildSupportOperatorMessage` и др.);
  PAN-подобные последовательности в свободном тексте redact'ятся перед DM.
- 403 от пользователя, не запустившего бота, обрабатывается (не роняет поток);
  сбой альбома скриншотов не блокирует выдачу VPN-ссылки.

## F7 · Общее для всех клиентов

- Каждый `fetch` — с `AbortController`-timeout (без исключений).
- Ретраи — только на идемпотентных операциях; мутирующие без идемпотентного
  ключа не ретраятся.
- Ответ каждого внешнего API — через Zod-схему из `@oplati/types`; дрейф →
  типизированная ошибка, не `as T`.
- Новый код, опирающийся на неподтверждённое поведение провайдера
  (нет живого вызова, нет доки владельца), — находка сам по себе.
