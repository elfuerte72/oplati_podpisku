# Ось D — Границы пакетов, архитектура, конвенции кода

Жёсткие правила из CLAUDE.md (разделы «Границы пакетов», «Конвенции кода»,
«Что запрещено»). Проверяется на любом diff. Нарушение границ ломает модульность
монолита — стоп-кран.

## D1 · Матрица импортов пакетов

| Пакет | Может импортировать | Запрещено |
|---|---|---|
| `@oplati/types` | только `zod` | любые `@oplati/*` |
| `@oplati/db` | `@oplati/types` | `@oplati/agent`, `apps/web` |
| `@oplati/agent` | `@oplati/types` | **`@oplati/db` напрямую** |
| `apps/web` | все `@oplati/*` | — |

- `@oplati/agent` общается с БД **только** через интерфейс `ToolHandlers`
  (реализация в `apps/web/lib/tool-handlers/`), не импортируя `@oplati/db`.
- ❌ Нарушение: `import ... from '@oplati/db'` в `packages/agent`; импорт
  `@oplati/*` в `packages/types`; импорт `@oplati/agent`/`apps/web` в
  `packages/db`; агент, дергающий БД мимо `ToolHandlers`.

## D2 · Только barrel / объявленные subpath-экспорты

- Импорты между пакетами — только через barrel или объявленные exports:
  `@oplati/db`, `@oplati/db/schema`, `@oplati/agent/tools`.
- ❌ Нарушение: приватные пути (`@oplati/db/src/...`, `@oplati/agent/src/...`);
  относительные cross-package импорты (`../../../packages/...`); импорт из
  `dist`/внутренностей чужого пакета.

## D3 · Нет кросс-импортов apps и циклов

- Кросс-импорты между `apps/*` запрещены. Циклы между пакетами запрещены.
- ❌ Нарушение: импорт из другого `apps/*`; взаимный импорт двух пакетов, образующий
  цикл.

## D4 · Инвариант единого агента

- Оба канала — Telegram-бот (`/api/bot`) и веб-чат (`/api/chat`) — используют
  **один** `runAgent()` из `@oplati/agent`. Логика диалога не форкается по каналу.
- ❌ Нарушение: отдельная ветка агента/промпта только для одного канала; дублирование
  tool-loop в обход `runAgent`.

## D5 · RSC по умолчанию

- Серверные компоненты по умолчанию; `"use client"` — только где реально нужен
  браузерный API (обработчики, `useState`/`useEffect`, `window`/`localStorage`).
- ❌ Нарушение: `"use client"` на компоненте без браузерного API; серверный секрет/
  `service_role`/прямой доступ к БД в client-компоненте; утечка серверного модуля
  (`server-only`) в клиентский бандл.

## D6 · Result pattern vs throw

- Ожидаемые неудачи — Result (`{ ok: false, reason }`). `throw` — только для
  неожиданного/невосстановимого.
- Graceful degradation на внешних (Anthropic, БД): понятный ответ пользователю, не
  `500`. Бот при недоступной БД отвечает, но «забывает» историю.
- ❌ Нарушение: `throw` на ожидаемой бизнес-неудаче на пользовательском пути; `500`/
  необработанный throw при сбое внешней зависимости вместо деградации.

## D7 · Строгие типы

- `strict: true` + `noUncheckedIndexedAccess` + `verbatimModuleSyntax`. `any`
  запрещён; недоверенное — `unknown` + Zod narrow.
- ❌ Нарушение: `any` (в т.ч. `as any`); `as T` без обоснования; `@ts-ignore`/
  `@ts-expect-error` без комментария-причины; доступ по индексу без учёта
  `undefined`.

## D8 · Именование

- `camelCase` функции/переменные, `PascalCase` типы/классы, `UPPER_SNAKE_CASE`
  compile-time константы, `snake_case` БД-колонки, `kebab-case.ts` файлы,
  `PascalCase.tsx` компоненты.
- ❌ Нарушение: файл `.ts` не в kebab-case; компонент-файл не в PascalCase;
  БД-колонка не в snake_case; таинственные/несогласованные имена.

## D9 · Без эмодзи в коде

- Эмодзи запрещены в коде, комментариях, логах. В русских UI-строках — допустимо,
  если требует продукт.
- ❌ Нарушение: эмодзи в идентификаторе/комментарии/`logger`-строке/commit-заголовке.

## D10 · Прочие запреты

- Никогда `pnpm --filter @oplati/db db:push --force` на prod. Никогда правка БД
  через Dashboard в обход Drizzle (перекрывается осью A5).
- ❌ Нарушение: скрипт/док, предлагающий `db:push --force` на prod; обход Drizzle.
