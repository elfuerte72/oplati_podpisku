# Ось E — Корректность, логика, обработка ошибок, тесты

Общая инженерная корректность поверх проектных инвариантов. Тесты оцениваются в
духе TDD: проверяют поведение через публичные seam'ы, не тавтологичны, не
привязаны к реализации.

## E1 · Логика и edge cases

- Проверь граничные условия: пустой ввод, `null`/`undefined`,
  `noUncheckedIndexedAccess`-случаи (доступ по индексу может дать `undefined`),
  пустые массивы, off-by-one, деление/остаток, отрицательные суммы, нулевой курс.
- Мёртвые ветки, недостижимый код, инвертированные условия, `===` vs `==`,
  перепутанные операнды.
- ❌ Симптомы: обращение к `arr[i].foo` без проверки; необработанный `undefined`
  из `.find()`/`Map.get()`; ветка, которая никогда не выполнится.

## E2 · Async / промисы / гонки

- Нет потерянных промисов (floating `await`-less вызовы async-функций). Нет гонок
  на общий ресурс без атомарной защиты (см. оси A4/B2).
- ⚠️ **Vercel замораживает функцию после ответа**: работа в `setImmediate`/
  `process.nextTick`/незаожиданном промисе после `res` — теряется. Фоновая доводка
  должна идти через cron/очередь, а не «после ответа».
- ❌ Симптомы: вызов async без `await`/`.catch`; `setImmediate(fulfillment)` в
  запросе; `Promise.all` без обработки reject; забытый `await` перед транзакцией.

## E3 · Обработка ошибок и деградация

- Внешние сбои (Anthropic, БД, L&P, PaySpace, Telegram) → понятная деградация, не
  `500` и не молчаливое проглатывание (перекрытие с осью C7, но здесь фокус на
  пользовательском исходе).
- Fail-open vs fail-closed **осознанно**: rate-limit/токен-бюджет — fail-open
  (недоступность защиты не должна ронять продукт); cron с побочными эффектами и
  guard'ы конфигурации (`isPaySpaceConfigured`) — fail-closed.
- ❌ Симптомы: `500` при таймауте Anthropic; fail-closed там, где нужен fail-open
  (лишний отказ клиенту), и наоборот (защита обходится при сбое).

## E4 · Денежные вычисления (корректность)

- Формула цены: `курс × USD-цена + COMMISSION_PERCENT` (+ `CARD_ISSUE_FEE_USD_CENTS`
  только без активной карты). Проверь порядок операций, округление, что итог
  совпадает с построчной разбивкой («Подписка / Выпуск карты / Итого»).
- Буфер карты `PAYSPACE_CARD_BUFFER_PERCENT` — только на карте, **не** в
  `original_amount` клиента; округление вверх.
- ❌ Симптомы: комиссия/буфер посчитаны на float; двойной учёт fee; расхождение
  суммы строк и итога; буфер попал в цену клиента.

## E5 · Покрытие тестами (Vitest)

- Новая логика/фикс бага — с тестами. Расположение: `apps/web` (unit/интеграция),
  `packages/types` (схемы, state machine), `packages/db` (интеграционные на
  **PGlite** — реальный Postgres + реальные миграции для БД-инвариантов, гонок,
  идемпотентности, RLS-триггеров).
- Баг-фикс — сначала red-тест на нужном seam, потом фикс (проект следует TDD).
- ❌ Симптомы: новый переход состояния / claim / начисление / граница без теста;
  фикс бага без регрессионного теста; изменена логика денег/идемпотентности без
  обновления тестов.

## E6 · Качество тестов

- Тест проверяет **поведение через публичный интерфейс** (seam), не приватные
  детали. Пережившие рефакторинг тесты — хорошие.
- **Не тавтологичен**: ожидаемое значение не выведено той же логикой, что и код
  (`expect(add(a,b)).toBe(a+b)` — плохо; ожидаемое берётся из спеки/известного
  значения). Для БД — проверяй реальный эффект в Postgres, а не мок внутренностей.
- **Вертикальные срезы**, не «все тесты скопом на предполагаемое поведение».
- ❌ Симптомы: мок внутреннего коллаборатора вместо проверки на seam; ассерт,
  повторяющий формулу кода; snapshot, посчитанный самим кодом; тест, зелёный при
  реальной поломке.

## E7 · Мелочи, роняющие прод

- `fetch` без timeout (перекрытие C6) на новом пути. Незакрытые ресурсы. Логика
  времени/таймзон в cron (`renewal-reminder` 07:00, `recycle-cards` пороги 90/180д).
- Идемпотентность cron-джобов при повторном запуске (Vercel Cron может дублировать).
- ❌ Симптомы: cron с побочным эффектом без дедупа/claim; сравнение дат без учёта TZ;
  таймер/интервал в serverless-пути.
