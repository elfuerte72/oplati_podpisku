# Глоссарий домена

Термины, у которых в коде и в разговоре с владельцем ОДНО значение. Создан лениво (правило
`docs/agents/domain.md`): пока сюда попали только термины трека поддержки — у остальных
подсистем словарь живёт в `CLAUDE.md`.

## Поддержка (трек support-ai, 2026-08-27)

- **Помощник** — AI-агент поддержки (`deepseek-v4-flash`). Представляется клиенту «помощник
  поддержки Оплатишки», на «вы», без маскота. **Не Оплатишка**: Оплатишка («ты», маскот)
  живёт в `/start` и в приложении. В коде — `lib/support/`, промпт `support-prompt.ts`.
- **Оператор** — живой сотрудник с правом `support`, отвечает из панели `/admin/support`
  через клиентского бота. Клиент видит его сообщения с автопрефиксом «Оператор: »; в БД
  текст без префикса (`role='operator'`, `staff_id`).
- **Сессия поддержки** — окно, внутри которого свободный текст клиента обрабатывает
  помощник. Открывается ТОЛЬКО кнопкой «Поддержка» / `/support` / deep-link `?start=support`
  (правило В3); гаснет через 30 мин молчания — лениво, при следующем входящем.
- **Режим разговора** — `conversations.handoff_mode`: `idle` (никто; свободный текст
  получает подсказку с кнопкой) · `ai` (сессия помощника) · `operator` (эскалировано;
  помощник молчит, отвечает человек). Срок режима — `mode_expires_at`; `NULL` в `operator`
  = «ждём человека, не гаснет никогда».
- **Эскалация / передача оператору** — переход `→ operator` через `escalate()` в
  `lib/support/session.ts`. Четыре источника: жёсткий триггер, tool `request_human`,
  выходной фильтр, авария модели. Триггер пишется в служебную строку и в аналитику.
- **Жёсткий триггер** — детерминированный список основ слов (`hard-triggers.ts`),
  проверяется ДО вызова модели: человек / деньги назад / претензия / документы. Отрицание
  срабатывает намеренно; «отзыв» — не триггер.
- **Выходной фильтр** — чистая функция по денилисту (`output-guard.ts`), проверяет ответ
  модели ПЕРЕД отправкой клиенту: партнёры, страна карты, процент/курс, внутренние
  идентификаторы. Срабатывание → нейтральная фраза клиенту + эскалация `guard`.
- **Захват** — атомарный переход разговора в `operator` с закреплением за сотрудником при
  условии «свободен или мой». Происходит при ответе из панели и при кнопке «подключиться».
  «Подключиться» ≠ «ответил»: срок режима при захвате обнуляется.
- **Служебная строка** — `messages` с `role='system'` и `meta.source='support_state'`,
  пишется при каждом состоявшемся переходе в той же транзакции. Видна в панели, клиенту не
  уходит, помощнику в историю не подаётся.
- **Кап** — 100 ответов помощника на клиента за скользящие сутки, считается по БД. При
  исчерпании сессия закрывается без эскалации (решение владельца).
