## [`history/`](history/) — архив

Исполненные планы, отчёты закрытых аудитов, устаревшие спеки, мокапы.
**Не удалять** — это история решений и фиксов, по ней восстанавливают «почему так».
**И не использовать как ТЗ:** каждый файл там описывает контур, которого уже нет.

Ключевое из архива:

- `dokploy-cutover-report.md` — переезд с Vercel+Supabase на Dokploy: верификация,
  код-ревью по 5 осям, все находки со статусами, смоук-чек-лист денежного пути
  (раздел 12 — им ещё пользуются);
- `dokploy-migration-plan.md` — план того же переезда, фазы 0–5, целевая архитектура;
- `audit-2026-07-18-fix-plan.md` — ТЗ по находкам полного аудита, закрыто;
- `spec-2026-06-referral-program.md` + `plan-2026-06-referral-program.md` — спека и
  план рефералки. ⚠️ описывают **трёхуровневую** сеть; программу упростили до
  одного уровня 2026-07-02, так что содержимое противоречит текущему коду;
- `plan-2026-06-phase2-payspace-cards.md` — фаза виртуальных карт.

## Как вести документацию в этом репозитории

Проект разрабатывается агентами, и это меняет требования к докам. Практика,
выведенная из собственных грабель:

1. **Один авторитетный файл инструкций** — `CLAUDE.md`. Не копии: копия
   инструкций уже расходилась с реальностью (находка F-20 аудита 2026-07-11), после
   чего `AGENTS.md` стал указателем, а не дублем.
2. **Инварианты — как жёсткие правила с указанием, чем обернётся нарушение.**
   «`order_events` append-only» без объяснения агент воспринимает как стиль;
   «форсится триггером БД, `UPDATE` бросает exception» — как контракт.
3. **Граница «актуально / история» должна быть физической.** Не пометкой внутри
   файла, а каталогом: всё в `history/` не читается как ТЗ. Иначе исполненный план
   выглядит как список задач.
4. **Знание, добытое перебором, записывать сразу и с ответами провайдера.**
   Контракт deploy-вебхука Dokploy, формат дампа `pg_dump -Fc`, поведение
   `askPrice` у Rapira — этого нет в чужой документации, и выяснять второй раз
   придётся на живом проде.
5. **Ровно один список «на потом»** — `BACKLOG.md`. Как только их два, оба
   становятся неполными.
6. **Дата и «почему отложено» обязательны.** Без них через месяц не отличить
   осознанное решение от забытого.
7. **Устаревшую запись удалять, а не оставлять.** Неверная документация опаснее
   отсутствующей: агент действует по ней уверенно.
