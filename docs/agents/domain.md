# Доменные документы

Как инженерные скиллы должны читать документацию этого репозитория при изучении кода.

## Раскладка — single-context

Репозиторий формально монорепо (`pnpm-workspace.yaml`, `packages/*`), но контекст один:
границы пакетов уже описаны таблицей в `CLAUDE.md`, а домен у всех пакетов общий — оплата
подписок. Поэтому `CONTEXT-MAP.md` и по-пакетные `CONTEXT.md` не заводим: один корневой
глоссарий + один `docs/adr/`.

```
/
├── CLAUDE.md          ← источник правды: устройство, инварианты, решения
├── CONTEXT.md         ← глоссарий домена (есть в корне, см. ниже)
├── docs/adr/          ← ADR новых решений
└── packages/, apps/
```

## Перед изучением кода прочитать

1. **`CLAUDE.md`** в корне — главный документ. Устройство контура, архитектурные
   инварианты, что осознанно не используем и почему.
2. **`docs/architecture.md`** — устройство кодовой базы подробнее.
3. **`CONTEXT.md`** в корне, если существует — глоссарий домена.
4. **`docs/adr/`** — ADR, затрагивающие область, в которой предстоит работать.

Если `CONTEXT.md` или `docs/adr/` нет — **продолжай молча.** Не сообщай об их отсутствии и не
предлагай создать их заранее. Скилл `/domain-modeling` создаёт их лениво, когда термин или
решение действительно потребовалось зафиксировать.

## Где ещё живут решения

ADR — новый для этого репозитория формат; исторические решения лежат в других местах, и при
изучении области их надо учитывать наравне с ADR:

- **`docs/CHANGELOG.md`** — история изменений с обоснованиями.
- **`docs/incidents.md`** — журнал инцидентов: что сломалось и почему.
- **`docs/history/`** — архив: исполненные планы, закрытые аудиты, устаревшие спеки.
  **Не ТЗ** — каждый файл описывает контур, которого уже нет.
- **`docs/BACKLOG.md`** — отложенное и открытые находки аудитов.

## Словарь

Когда результат работы называет доменное понятие (заголовок тикета, предложение по
рефакторингу, гипотеза, имя теста), используй термин так, как он определён в `CONTEXT.md`, а
при его отсутствии — как в `CLAUDE.md` и коде. Не уходи в синонимы.

Если нужного понятия в словаре нет — это сигнал: либо ты выдумываешь язык, которого в проекте
нет (пересмотри), либо есть реальный пробел (отметь для `/domain-modeling`).

Отдельно про расхождение UI и кода: **в интерфейсе термин «статус», в коде и БД идентификатор
остался `circle`/`current_circle`** — это осознанно, переименовывать не надо.

## Конфликт с ADR — сообщать явно

Если результат работы противоречит существующему ADR, скажи об этом вслух, а не переопределяй
молча:

> _Противоречит ADR-000N (…) — но стоит переоткрыть, потому что…_

**То же правило действует для `CLAUDE.md`:** он источник правды наравне с кодом. Расхождение с
ним — находка, о которой надо сказать, а не молча сделать по-своему. Если документ противоречит
коду — прав код.
