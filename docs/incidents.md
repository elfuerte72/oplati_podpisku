# Журнал инцидентов и отложенных рисков

Операционные инциденты прода и осознанно отложенные проблемы. Правила ведения:
новый инцидент — сверху секции «Открытые», с датой, влиянием и следующим шагом;
закрытый — переносится в «Закрытые» с описанием развязки. Технические детали
кода — в CLAUDE.md/коде, здесь только операционная суть и кто что должен сделать.

Статусы: **ОТКРЫТ** (требует действия) · **ПРИНЯТ** (осознанный риск, действий не будет) · **ЗАКРЫТ**.

## Открытые

### 2026-07-03 — ORD-93RQE: оплата принята, карта не пополнена (Insufficient VCC balance) — ОТКРЫТ

- **Что случилось:** клиент thomas оплатил App Store $20 (2 002 ₽, 15:41 UTC), вебхук L&P
  принял платёж, но топап карты упал: `PaySpaceApiError: Insufficient balance on VCC
  subaccount` → заказ в `failed`. Деньги приняты, услуга не оказана. Рядом — постоянный
  алёрт `vcc_balance.low` (148 событий за ~2 недели, порог $50).
- **Смягчение:** у клиента уже есть активная карта с реквизитами (получасом раньше
  успешно купил YouTube Premium, ORD-DJV61) — его App Store-заказ это топап той же карты.
- **Действия (владелец):**
  1. Пополнить VCC-субаккаунт PaySpace — СРОЧНО (пополнение с крипто-баланса T+1 + ~3% fee).
  2. После пополнения вручную топапнуть карту клиента на $20 + буфер (PaySpace-кабинет)
     или решить возврат 2 002 ₽.
  3. Учесть: авто-recovery заказ в `failed` не подхватывает (poll-payment поднимает только
     зависшие `paid`).
- **Связь с клиентом:** новый бот не может написать ему первым (см. инцидент про переезд
  бота ниже) — либо дождаться его Start/обращения в поддержку, либо исполнить молча
  (реквизиты карты у него уже есть).

### 2026-07-03 — Vercel DEPLOYMENT_PAUSED: прод лежал, причина не выяснена — ОТКРЫТ (мониторить)

- **Что случилось:** во время переезда бота Vercel поставил проект на паузу
  (`DEPLOYMENT_PAUSED`): сайт, вебхуки бота/L&P и кроны были недоступны ~30 минут,
  новые деплои висели в BLOCKED.
- **Как сняли:** `POST https://api.vercel.com/v1/projects/<id>/unpause` (авторизация —
  токен Vercel CLI). После unpause `vercel redeploy <url>` пересобрал прод.
- **Риск:** причина паузы не установлена (Spend Management? биллинг Pro-плана?) —
  может повториться.
- **Действие (владелец):** проверить Vercel → Settings → Billing / Spend Management,
  найти причину паузы и убрать её (лимит расходов / способ оплаты).

### 2026-06-* — USDT/RUB rate fallback used: живой курс не тянется — ОТКРЫТ (отложено)

- **Что происходит:** Sentry-warning `USDT/RUB rate fallback used` — 176 событий за
  2 недели: при каждом propose курс падает на fallback 77 ₽ вместо живого из L&P `/rates`.
- **Влияние:** при реальном курсе выше 77 маржа занижается на каждом заказе.
- **Действие:** разобраться, почему `getRates` не отдаёт живой курс (ключи/эндпоинт/схема),
  либо осознанно поднять fallback.

## Принятые риски

### 2026-07-03 — Клиенты старого бота недостижимы для сообщений — ПРИНЯТ

- Прод-бот переехал `@test_prodipsa_bot` → `@oplatishkaa_bot` (смена токена), старый бот
  удалён из BotFather. Новый бот не может написать первым клиентам, которые не нажали
  у него Start: чеки, реквизиты карт и уведомления об оплате им не доставятся.
- Рассылка «мы переехали» со старого бота невозможна (бот удалён). Клиенты
  восстанавливаются сами: все ссылки сайта/mini app ведут на нового бота.
- Держать в голове при ручном фулфилменте старых клиентов (см. ORD-93RQE).

### 2026-07-03 — Токен нового бота засвечен в чате сессии — ПРИНЯТ

- Токен `@oplatishkaa_bot` был отправлен владельцем в чат Claude Code. Ротация предложена,
  владелец отказался («никому не нужен»). При подозрении на компрометацию: BotFather →
  Revoke → новый токен в Vercel UI (Production `TELEGRAM_BOT_TOKEN`) + локальный `.env` →
  redeploy (вебхук перерегистрировать не нужно — URL и секрет не меняются).

### 2026-07-03 — Месячный тариф Telegram Premium скрыт с витрины — ПРИНЯТ (до решения)

- $4.99 × курс 77 × 1.30 = 499,50 ₽ — ниже минимума терминала L&P (500 ₽). Витрина
  автоматически скрывает неоплатимые тарифы, клиентам виден только годовой ($35.99 →
  3 602,60 ₽). Варианты, если нужен месячный: тарифы 3/6 мес (цены подтвердить),
  договориться с L&P о минимуме, пересмотреть fallback-курс.
