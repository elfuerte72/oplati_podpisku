Что видит клиент от первого экрана до оплаченной подписки: витрина, пер-сервисные правила
оплаты, прозрачная цена, Mini App-кабинет с картой и пост-выпускные статусы заказа.

Выделено из `CLAUDE.md` 2026-08-14. Дизайн-система и брендовые правила — skill
`oplatishka-design`; тексты и поведение AI — `packages/agent/src/prompts.ts`.

⚠️ **Страна выпуска карты публично НЕ указывается** — «виртуальная карта», не «американская» и
не «карта США». Проверять при добавлении любых текстов.

# Личный кабинет — Telegram Mini App `/cabinet`

`components/cabinet/`, бэкенд `POST /api/cabinet`. **Авторизация — проверка подписи `initData` на
каждом запросе** (`lib/cabinet/auth.ts`).

## Экраны

Кнопочный каталог «сервис → тариф/сумма → заказ» (`CatalogView`, action `propose` → общий
`proposeFromCatalog`, channel `telegram`) → экран заказа с построчной разбивкой цены и кнопкой
«Оплатить» (`payOrder` → ссылка шлюза через `tg.openLink`) → карта клиента с разовым показом
реквизитов (`card-details`, live из PaySpace) → вход в партнёрку.

**Реф-ссылка вынесена прямо в главное меню** — карточка «Скопировать» / «Поделиться», поле
`referralLink` в снапшоте `/api/cabinet` за флагом `REFERRAL_ENABLED`.

UI на SVG-иконках комикс-стиля (`components/comic/icons.tsx`), не на эмодзи (2026-07-03).

**Списка заказов (истории покупок) осознанно НЕТ** (решение владельца 2026-07-02) — снапшот
`orders` бэкенд по-прежнему отдаёт, UI не рендерит.

Убраны 2026-07-03: кнопки «Повторить заказ» и «Нужен оператор»; их серверные actions
`repeat`/`operator` удалены из `/api/cabinet` 2026-07-19 (L-9).

## Контакты плательщика и «Проблема с оплатой» (антифрод-трек 2026-08-15)

- **Плашка контактов** на экране заказа — общий `components/contacts/ContactCard.tsx`,
  живёт и в Mini App (`OrderDetailView`), и на сайте (payment-карточка чата). Email
  обязателен всегда (без него `payOrder`/`confirm` вернёт `422 email_required`);
  поле телефона появляется только при сумме от порога `PHONE_REQUIRED_FROM_RUB`
  (порог приходит с сервера — `/api/profile` и cabinet-snapshot, в UI не зашит).
  Кнопка «Взять из Telegram» зовёт `requestContact`: номер приложению НЕ отдаётся —
  он приходит боту contact-сообщением, поэтому после подтверждения экран
  перезагружает снапшот с задержкой.
- **Экран «Профиль»** в Mini App (`ProfileView`, action `update-contacts`) — просмотр
  и правка email/телефона; ручная правка помечает `phone_source='manual'` (номер из
  Telegram — `'telegram'`, верифицированный путь).
- **Кнопка «Проблема с оплатой»** — на заказе до выпуска карты (ждёт оплаты / на
  проверке / истёкший свежее 48 ч), Mini App + сайт (`PaymentProblemPanel`, роут
  `POST /api/orders/problem`). «Я оплатил» переводит заказ «на проверку банка»
  и шлёт DM оператору (дедуп час); «Хочу возврат» — DM без автоматики; «Другая
  проблема» — подсказка `/support`.
- **Статус «Платёж на проверке банка»** (`payment_review`) виден на экране заказа:
  заказ не протухает, исход (оплата подтверждена / отказ) приходит сообщением бота.

## Вход через `/start` бота

GREETING (короткое дружелюбное приветствие; без USDT, оператора и «напиши что нужно» — переписано
2026-07-03) с inline-меню `buildStartMenuKeyboard`:

- web_app-кнопка «Открыть приложение» — `miniAppUrl()`;
- url-кнопка **«Сайт»** — `siteUrl()` + `/?src=tg`, анти-петля с мобильным баннером «Продолжить в
  Telegram»;
- «Поддержка» — callback `support`;
- url-кнопка **«Telegram-канал»** — `TELEGRAM_CHANNEL_URL` (`telegram.me/ooplatishka`, канал создан
  2026-07-10; callback `channel` оставлен для уже отправленных старых меню и отвечает ссылкой).

`setMyCommands` — только `/support`; `/menu` убран, он не работает при выключенном
`BOT_AI_ENABLED`. Постоянная reply-клавиатура на `/start` больше не ставится, но тексты старых
reply-кнопок («Выбрать сервис», «Написать в поддержку») по-прежнему перехватываются — у
существующих пользователей клавиатура осталась.

# Клиентский путь (ТЗ 2026-07-18, задеплоено PR #81)

## 1. Первый экран сайта

УТП «Оплачивай зарубежные подписки рублями» + три галочки, кнопки «Выбрать сервис» и «Как это
работает» (онбординг 3 шага с прогрессом «N из 3» — `components/chat/HowItWorksOverlay.tsx`,
подпись «Итоговую сумму увидишь до оплаты»).

## 2. Пер-сервисные правила оплаты

`services.payment_instructions` (jsonb, миграция 0022; Zod `servicePaymentInstructions` в
`@oplati/types`: `requiresVpn`, `vpnLocation`, `requiredCurrency`, `billingInstructions`,
`paymentUrl`, `paymentNotes`; seed заполняет 13 активных сервисов) → витрина
(`CatalogService.instructions`) → блок «Важно перед оплатой»
(`components/catalog/ServiceInstructions.tsx`) на карточке сервиса (web `StartScreen` + Mini App
`CatalogView`) и на экране заказа.

VPN больше НЕ общий совет (ТЗ §5). Битая запись не прячет сервис: `instructions: null` →
generic-текст.

## 3. Прозрачная цена

Кнопка оплаты содержит сумму («Оплатить 2 490 ₽» — web `ChatClient` + Mini App
`OrderDetailView`), рядом раскрывашка «Как рассчитана сумма» (цена в $, зафиксированный курс из
`orders.usdt_rub_rate_kopecks`, комиссия, выпуск карты) и подпись «Цена зафиксирована до
<expiresAt>».

## 4. Экран карты в кабинете

**Live-баланс.** Снапшот кабинета тянет реальный баланс из PaySpace `getCardInfo` для основной
карты с бюджетом 4 с и кэширует в БД через `syncCardBalance` — БД-снимок сам по себе не видит
списаний клиента на сайте сервиса. Сбой или таймаут → показываем последний известный снимок
(`lib/cabinet/live-balance.ts`).

`syncCardBalance` — **compare-and-set** по прочитанному балансу: проиграв гонку параллельному
topup из `issue-card`, кэш не трогаем. И осознанно НЕ трогает `last_used_at` — иначе просмотр
кабинета мешал бы recycle-cron.

**«Действует до» — РАНЬШАЯ из двух дат** (`cardValidUntil`): `exp_date` карты у провайдера
(MM/YY, конец месяца) и `createdAt + CARD_LIFETIME_DAYS` (180 дней, синхронно с recycle-cron).
Карта умирает от любой, поэтому обещать можно только минимум. Показывается **с годом**
(`formatDeadlineWithYear`; `formatExpires` без года остаётся счетам, которые живут час).

> До 2026-07-30 брался безусловно `exp_date`, и витрина обещала срок платёжной сети: у карты с
> `exp_date=06/30` кабинет писал «30 июня» — 2030! — при фактическом закрытии в декабре 2026.
> Обещание денежное, рядом сказано про надбавку за выпуск новой.

Плюс строка «Для оплаты: <сервис последнего заказа>», кнопки «Перейти на сайт сервиса»
(`paymentUrl`) / «Инструкция» / «Не проходит оплата?». Показанные реквизиты автоскрываются через
60 с (ТЗ §4).

## 5. Пост-выпускные статусы заказа

«Ожидает оплаты на сайте сервиса» / «Подписка оплачена» / «Возникла проблема» — производные от
append-only событий `subscription_activated` и `payment_issue_reported` в `order_events`.
**Статус-машина НЕ тронута, `completed` терминален.**

Действия `/api/cabinet`, оба под серверным гейтом `status='completed'`:

- **`payment-issue`** — чек-лист самопроверки + выбор типа проблемы. Оператору автоматически
  уходит контекст: номер заказа, сервис, тариф, сумма, статус карты, тип ошибки
  (`buildPaymentIssueOperatorMessage`, с redact PAN-подобных последовательностей в комментарии
  клиента; доставка через общий `lib/telegram/support.ts`, дедуп 5 мин);
- **`subscription-paid`** — идемпотентно.
