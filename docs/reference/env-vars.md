# Справочник переменных окружения

Что читает код, зачем и что будет, если не задать. Источник правды —
[`apps/web/lib/env.ts`](../../apps/web/lib/env.ts): если переменной нет в схеме
там, приложение её не видит, сколько ни задавай.

> **Значений здесь нет и быть не может — репозиторий публичный.** Секреты живут
> в env приложения Dokploy (`oplatishka-web` / `oplatishka-web-dev`) и в
> корневом `.env` для локальной разработки.

**Как читать колонку «Если не задать»:** «падает старт» = приложение не
поднимется вовсе; «функция выключена» = всё остальное работает, отвалится
только эта часть.

## Приложение

| Переменная | Что это | Если не задать |
|---|---|---|
| `NODE_ENV` | `production` на сервере, `development` локально | по умолчанию `development` |
| `APP_URL` | публичный адрес сайта. От него строятся ссылки: страница успеха оплаты, кнопка «Сайт» в боте, презентация партнёрки | **падает старт** — единственная безусловно обязательная переменная |
| `MINIAPP_BASE_URL` | отдельный адрес для Mini App-кабинета, если он должен открываться мимо основного домена | кабинет открывается по `APP_URL` |
| `SELF_BASE_URL` | адрес для внутреннего вызова «выставить счёт» самому себе. На сервере `http://127.0.0.1:3000` — денежный вызов идёт внутри контейнера, не выходя в интернет | fallback на внешний адрес: работает, но зависит от сети и Traefik |
| `LOG_LEVEL` | подробность логов (`info` / `debug` / …) | `info` на сервере, `debug` локально |

## База данных

| Переменная | Что это | Если не задать |
|---|---|---|
| `DATABASE_URL` | адрес + логин + пароль базы. Через него ходит всё приложение | **всё, что связано с БД, падает**: заказы, платежи, история. Сайт откроется, покупка — нет |
| `DATABASE_URL_DIRECT` | прямое подключение в обход пула — для миграций | миграции берут `DATABASE_URL` |
| `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` | **легаси эпохи Supabase.** В рантайме НЕ используются — SDK Supabase из кода удалён, вся работа с БД идёт напрямую по `DATABASE_URL` | ничего не произойдёт. Можно удалить из env прода |

## Админ-панель (`/admin`)

Вход в панель — Telegram Login Widget (первый фактор) плюс код из приложения
(TOTP, второй). Паролей нет. Бот входа — **третий бот контура**,
`@oplatishkaasupport_bot` (id `7992756364`): клиентский бот для входа персонала
не используется, потому что утечка клиентского токена не должна отдавать первый
фактор. ⚠️ Имя бота говорит «support», но это бот **персонала** — он же
доставляет уведомления менеджеру; клиентская поддержка живёт в
`@oplatishkaa_bot`.

| Переменная | Что это | Если не задать |
|---|---|---|
| `TELEGRAM_LOGIN_BOT_TOKEN` | ключ бота входа. Им проверяется подпись кнопки Telegram и им же шлются уведомления менеджеру | **в панель не войти никому** |
| `TELEGRAM_LOGIN_BOT_USERNAME` | имя бота без `@` — нужно кнопке входа на странице | кнопка входа не появляется, панель говорит об этом прямо |
| `TELEGRAM_LOGIN_BOT_WEBHOOK_SECRET` | пароль точки приёма бота персонала (`/api/staff-bot`). Свой, **не общий** с клиентским ботом | бот персонала молчит на `/start`, и сотрудник не понимает, подключены ли уведомления |
| `ADMIN_SESSION_SECRET` | подпись cookie сессии панели. Минимум 32 символа (`openssl rand -hex 32`) | **в панель не войти никому** |
| `PANEL_HOST` | домен панели (`admin.oplatishka.com`). Задан — `/admin` и `/api/panel` на любом другом домене отдают 404 | **на проде панель закрыта целиком** (fail-closed: потеря переменной не должна выставлять панель на публичный домен — прецедент `CLIENT_IP_MODE`). В локальной разработке гейт выключен |

Заведение сотрудника — скриптом, не формой:

```bash
pnpm --filter @oplati/db db:staff add <telegram_id> <email> <admin|operator> <имя>
pnpm --filter @oplati/db db:staff list
pnpm --filter @oplati/db db:staff reset-totp <telegram_id>   # потерял телефон
pnpm --filter @oplati/db db:staff disable <telegram_id>      # отзыв доступа, действует сразу
```

⚠️ Секрет TOTP скрипт не выдаёт: его генерирует сама панель при первом входе и
показывает сотруднику один раз. Так секрет не проходит через терминал и историю
команд.

⚠️ Каждый сотрудник обязан **один раз запустить бота входа** — Telegram не даёт
писать тому, кто не запускал бота, и уведомления до него не дойдут.

## Приём денег

### Переключатель

| Переменная | Что это | Если не задать |
|---|---|---|
| `PAYMENT_PRIMARY_PROVIDER` | **кто принимает рубли прямо сейчас**: `loveandpay` или `freekassa`. Влияет только на создание нового счёта; вебхуки обоих провайдеров работают всегда | `loveandpay` — шлюз, проверенный живыми деньгами. ⚠️ Опечатка (`Freekassa`, `true`) **роняет старт** — намеренно: молча уйти на другой шлюз хуже, чем не подняться |
| `PAYMENT_AUTO_FALLBACK` | если основной шлюз не ответил (таймаут / сеть / 5xx) — выставить счёт вторым. `1` = включить | выключено. Включать только когда оба шлюза проверены живыми деньгами |

### Love&Pay

| Переменная | Что это | Если не задать |
|---|---|---|
| `LOVEANDPAY_API_KEY` | ключ доступа к API | счета не выставляются |
| `LOVEANDPAY_SECRET_KEY` | ключ, которым подписываем **наши исходящие** запросы | то же |
| `LOVEANDPAY_WEBHOOK_SECRET` | ключ, которым проверяем **их входящие** уведомления об оплате | уведомления отвергаются: деньги придут, заказ не обработается. Дожмёт cron за ≤5 мин |
| `LOVEANDPAY_BASE_URL` | адрес их API | боевой адрес |
| `LOVEANDPAY_MIN_AMOUNT_RUB` | минимальная сумма счёта. Терминал не принимает меньше 500 ₽. **Этот же порог прячет дешёвые тарифы в каталоге** | 500 |
| `LOVEANDPAY_PROXY_URL` | исходящий прокси. Нужен был на Vercel, где IP плавал, а L&P пускает только с задекларированного. Сейчас приложение живёт на том самом сервере — прокси не нужен | прямое соединение (текущее состояние). Оставлено на случай отката на Vercel |

### Freekassa

| Переменная | Что это | Если не задать |
|---|---|---|
| `FREEKASSA_API_KEY` | ключ, которым подписываем **наши исходящие** запросы | при `PAYMENT_PRIMARY_PROVIDER=freekassa` **падает старт**; иначе Freekassa просто не используется |
| `FREEKASSA_SHOP_ID` | ID магазина, обязателен в каждом запросе. ⏳ **выдаётся при активации кабинета** | то же |
| `FREEKASSA_SECRET_WORD_2` | ключ, которым проверяем **их входящие** уведомления | то же |
| `FREEKASSA_SECRET_WORD_1` | **кодом не читается.** Подписывает только SCI-форму (оплата через форму в браузере), а мы работаем через API. Лежит про запас | ничего не произойдёт |
| `FREEKASSA_BASE_URL` | адрес их API | боевой адрес |
| `FREEKASSA_METHOD_ID` | способ оплаты: `44` = СБП, `36` = карты РФ | 44 (СБП) |
| `FREEKASSA_FALLBACK_IP` | IP плательщика, когда настоящий неизвестен (заказ из бота или Mini App). Провайдер требует IP и блокирует `127.0.0.1`, поэтому шлём адрес нашего сервера | IP нашего VPS |
| `FREEKASSA_INVOICE_TTL_HOURS` | сколько ждём оплату. **Провайдер срок жизни счёта не сообщает вовсе** — это наше решение | 1 час |
| `FREEKASSA_MIN_AMOUNT_RUB` | минимальная сумма счёта | 500 — тот же порог, что у L&P, чтобы переключение не меняло, какие заказы можно оформить |
| `FREEKASSA_MAX_AMOUNT_RUB` | потолок суммы счёта (лимит операции провайдера — 150 000 ₽) | 140 000 — запас на комиссию покупателя; 0 = гейт выключен |
| `FREEKASSA_BUYER_FEE_PERCENT` | комиссия, которую провайдер накручивает ПЛАТЕЛЬЩИКУ (только для текстов-предупреждений). ⚠️ Зеркало ползунка «Магазин ↔ Покупатель» в кабинете Freekassa | 0 — тексты о надбавке не показываются |
| `FREEKASSA_SEND_TEL` | слать ли телефон плательщика в `tel` запроса создания заказа (антифрод-трек, тикет 07). ⚠️ Включать ТОЛЬКО после живого подтверждения контракта: параметр в доке провайдера не описан | выключено — `tel` не отправляется |
| `FREEKASSA_ALLOWED_IPS` | с каких IP принимаем уведомления, через запятую | **пусто = рекомендуется**: несовпадение только алёртим, уведомление принимаем. Жёсткий список опасен — провайдер может сменить адреса молча, и приём денег встанет без симптомов. Подпись остаётся жёстким гейтом |

## Что важно знать про env в Dokploy

1. **Изменения применяются только при следующем деплое или перезапуске.** Пока
   контейнер работает, он держит старые значения.
2. **Значения не экранируются.** Проверено на dev-стенде: `$` не подставляется
   как переменная, одинарные кавычки снимаются, значение доходит байт в байт.
   Секретное слово Freekassa содержит `$`, `{`, `[` — писать можно как есть.
3. **Комментарии (`#`) поддерживаются** — можно держать пояснения прямо рядом
   со значением.
4. ⚠️ **Панель показывает все значения открытым текстом.** Доступ к панели =
   доступ ко всем ключам сразу. Отсюда задача «прикрыть панель» в бэклоге.
5. **На dev-стенде платёжных ключей нет намеренно** (ни L&P, ни Freekassa, ни
   PaySpace): иначе тестовый заказ выставил бы реальный счёт и выпустил карту за
   реальные деньги. `PAYMENT_PRIMARY_PROVIDER=freekassa` там задавать **нельзя** —
   dev-приложение перестанет запускаться.
