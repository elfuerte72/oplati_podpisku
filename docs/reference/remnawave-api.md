# Remnawave API — интеграция VPN в Оплатишку (справочник для агента-разработчика)

Назначение: бэкенд Оплатишки (Next.js, `oplati_podpicky`) по кнопке **🛡 VPN** в Telegram-боте
создаёт/находит пользователя в панели Remnawave, отдаёт ему **ссылку-подписку** и пишет её в БД.
На оплате (Love&Pay) — продлевает; на истечении — отключает.

---

## ⛔ Инвариант безопасности (не нарушать)

- **API-токен Remnawave живёт ТОЛЬКО на бэкенде** (env / секрет-менеджер). **Никогда** в браузере, во фронте, в Telegram-WebApp, в логах, в git. Зеркалит паттерн PaySpace/Love&Pay: токен — серверный.
- Панель `panel.mxpkn8ns.ru` наружу за логином; **все вызовы API — только server-side** (route handler / server action / бот-бэкенд), не с клиента.
- Для Оплатишки завести **отдельный API-токен** (не мастер-токен владельца) — чтобы можно было отозвать независимо. Как выпустить — см. в конце.

---

## Базовое

- **Base URL:** `https://panel.mxpkn8ns.ru/api`
- **Auth:** заголовок `Authorization: Bearer <TOKEN>`, `Content-Type: application/json`
- **Домен подписок (то, что уходит клиенту):** `https://sub.mxpkn8ns.ru/api/sub/<shortUuid>`
- **Squad по умолчанию** (в него кладём юзера, чтобы он получил ОБА подключения — Lithuania + «При белых списках»):
  `Default-Squad` = `e819a231-6e10-46c6-8411-7001dd67e9e1`
- Формат ответа панели: `{ "response": { ...данные... } }` — полезное всегда в `response`.
- Полный контракт/OpenAPI: **https://docs.rw** (там же схемы DTO). Ниже — проверенные на живой панели вызовы.

## Ключевой момент про «подписку»

Одна ссылка-подписка на юзера отдаёт **список подключений** (сейчас два: `🇱🇹 Lithuania` и `🇷🇺 При белых списках`).
Клиент (Happ / v2rayTun) добавляет ЭТУ ссылку — и сам видит оба сервера, переключается между ними.
Бэкенду **не нужно** генерировать конфиги — только получить `subscriptionUrl`.

⚠️ **Но одной ссылки-подписки может быть недостаточно** — см. раздел «Доставка конфига при белых списках» ниже.

## Подтверждено живыми вызовами (2026-07-21, реализация в коде)

Контракт снят с живой панели при внедрении кнопки «VPN» в боте:

- `POST /api/users` → **201**, `response.uuid/shortUuid/subscriptionUrl` — как выше.
- `GET /api/users/by-telegram-id/{tgId}` → **200 + `{"response": []}`** для несуществующего
  telegramId (НЕ 404) — «юзера нет» определяется пустым массивом.
- `POST /api/users/{uuid}/actions/revoke` (тело `{}`) → **200**, у юзера НОВЫЙ `shortUuid`
  и `subscriptionUrl` (старая ссылка умирает сразу), `expireAt` сохраняется,
  проставляется `subRevokedAt`. Это и есть «обновить ссылку» — юзер панели тот же.
- `DELETE /api/users/{uuid}` → **200 + `{"response":{"isDeleted":true}}`**.

Реализация: Zod-контракт — `packages/types/src/remnawave.ts`; HTTP-клиент —
`apps/web/lib/remnawave/` (Bearer из `REMNAWAVE_API_TOKEN`, timeout 10s, без ретраев);
флоу бота — `apps/web/lib/telegram/vpn-flow.ts` (callback `vpn` / `vpn:refresh`);
снимок — таблица `vpn_subscriptions` (миграция 0024). Продление по оплате — следующий этап.

## Подтверждено живыми вызовами (2026-07-29, замеры под вопросы бэкенда)

- **`revoke` ротирует И `shortUuid`, И `vlessUuid`.** Замер: создан `revoke_probe_0729`,
  `vlessUuid d85ec179… → 12ea159a…`, `shortUuid yWUb5g2e… → admDMMHd…`, юзер удалён.
  **Следствие: отзыв доступа работает и для конфигов, розданных текстом** — старая строка
  `vless://` перестаёт пускать. Опасение «revoke не отзовёт розданные конфиги» снято.
- **Эндпоинт подписки отдаёт base64 при ЛЮБОМ непустом User-Agent.** Проверено на
  `Happ/1.0`, `v2rayNG/1.8.5`, `Mozilla/5.0 (Macintosh)` — во всех случаях base64.
  **С пустым UA → JSON `{"isFound":false,"statusCode":404}`.** То есть обязателен не
  конкретно `Happ/1.0`, а просто наличие UA. Тело — всегда base64, plain-text не наблюдался.
- **`sub.mxpkn8ns.ru` резолвится в `177.7.34.106` (Boston, США)** — подтверждено фактическим
  `remote_ip` при HTTPS-запросе, не со слов.

## Эндпоинты, которые нужны

### 1. Найти юзера по Telegram ID (проверить, есть ли уже)
```
GET /api/users/by-telegram-id/{telegramId}
```
Вернёт массив/юзера, если существует. Если нет — создаём (шаг 2). Идемпотентность: **не плодить дубли** на один telegramId.
(Есть и `GET /api/users/by-username/{username}`, `GET /api/users/{uuid}`.)

### 2. Создать юзера
```
POST /api/users
```
Тело (минимум):
```json
{
  "username": "tg_123456789",
  "telegramId": 123456789,
  "expireAt": "2026-08-21T00:00:00.000Z",
  "trafficLimitBytes": 214748364800,
  "trafficLimitStrategy": "MONTH",
  "activeInternalSquads": ["e819a231-6e10-46c6-8411-7001dd67e9e1"]
}
```
- `username` — уникальный, латиница/цифры/`_` (например `tg_<telegramId>`).
- `telegramId` — число (связывает юзера панели с ТГ-юзером; по нему потом ищем).
- `expireAt` — ISO-8601 UTC, дата окончания доступа.
- `trafficLimitBytes` — лимит трафика в байтах (`0` = безлимит). Пример: `200 ГБ = 214748364800`.
- `trafficLimitStrategy` — `NO_RESET` | `DAY` | `WEEK` | `MONTH` (когда обнулять счётчик).
- `activeInternalSquads` — массив uuid сквадов (обязательно Default-Squad, иначе подписка пустая).

**Ответ (`response`) содержит всё нужное:**
```json
{
  "uuid": "6a2a8882-...",                // ← ГЛАВНЫЙ id для будущих update/disable (храни в БД)
  "username": "tg_123456789",
  "shortUuid": "V09yNf4WMN3EmLRn",
  "subscriptionUrl": "https://sub.mxpkn8ns.ru/api/sub/V09yNf4WMN3EmLRn",  // ← отдать юзеру + в БД
  "status": "ACTIVE",
  "expireAt": "2026-08-21T00:00:00.000Z",
  "telegramId": 123456789,
  "trafficLimitBytes": 214748364800,
  "vlessUuid": "480b4e7a-..."            // внутренний id протокола, бэкенду не нужен
}
```
> Важно: для дальнейших операций храни **`uuid`** (это `response.uuid`), а НЕ `vlessUuid`.

### 3. Продлить / изменить юзера (оплата, смена плана)
```
PATCH /api/users
```
Тело:
```json
{ "uuid": "6a2a8882-...", "expireAt": "2026-09-21T00:00:00.000Z", "trafficLimitBytes": 322122547200 }
```
Меняет только переданные поля. Так продлеваем по вебхуку оплаты.

### 4. Отключить / включить юзера
```
PATCH /api/users
{ "uuid": "6a2a8882-...", "status": "DISABLED" }
```
`status`: `ACTIVE` | `DISABLED` | `LIMITED` | `EXPIRED`. Отключение сразу рубит доступ (панель снимает юзера с нод).
Панель и сама переведёт в `EXPIRED`/`LIMITED` по `expireAt`/лимиту — можно полагаться на это и просто ставить срок.
> Проверь в OpenAPI, нет ли отдельных `.../actions/enable|disable` — если есть, используй их (семантика та же).

### 5. Показать статус/трафик юзера (для «мой VPN» в боте)
```
GET /api/users/{uuid}   (или by-telegram-id)
```
В ответе: `status`, `expireAt`, `userTraffic.usedTrafficBytes`, `trafficLimitBytes`, `subscriptionUrl`.

## Поток кнопки 🛡 VPN (MVP)

1. Юзер жмёт «VPN».
2. Бэкенд: `GET /api/users/by-telegram-id/{tgId}`.
   - Есть → берём `subscriptionUrl` из ответа.
   - Нет → `POST /api/users` (username `tg_<tgId>`, telegramId, expireAt = сейчас + пробный срок или срок оплаченного плана, Default-Squad).
3. Бэкенд отправляет юзеру **`subscriptionUrl`** + короткую инструкцию (поставить Happ → «добавить подписку по URL» → вставить).
4. Бэкенд делает **upsert в БД** (см. схему).
5. (Позже) Оплата Love&Pay → вебхук → `PATCH /api/users` продлить `expireAt` → обновить БД.

## 🔴 Доставка конфига при белых списках (обязательно к реализации)

### Проблема (подтверждена данными панели, 2026-07-28)

`subscriptionUrl` живёт на домене `sub.mxpkn8ns.ru` → это **Boston, США (`177.7.34.106`)**.
Чтобы получить конфиг, приложение юзера должно сходить на зарубежный IP.

При отключении мобильного интернета в РФ (режим «белых списков», центр Москвы, вахты, шатдауны
из-за БПЛА) оператор пропускает трафик **только к разрешённым российским сервисам**. Зарубежный IP
не проходит → подписка не скачивается → **в приложении пустой список серверов, подключаться не к чему**.

Юзер при этом не узнаёт даже про российский узел «При белых списках» — его адрес лежит внутри той
самой подписки, которую невозможно скачать. Классическая курица-яйцо.

**Факты из панели на 2026-07-28:** 7 юзеров из 14 (`neverOnline`) не подключались НИ РАЗУ — ноль байт
за всё время. При этом инфраструктура исправна: активные юзеры намотали 22 ГБ / 1,9 ГБ / 858 МБ,
российский вход (`ru-bridge`) пропустил 7,7 ГБ.

⚠️ **Это корреляция, а не доказанная причина.** Кнопка VPN выдаёт доступ бесплатно всем нажавшим,
и «7 из 14 не подключились» одинаково хорошо объясняется тем, что человек просто не поставил Happ.
К тому же юзеры панели — не только выдачи Оплатишки.
**Прежде чем менять флоу — свести `vpn_subscriptions` с трафиком панели:** сколько выдач сделала
Оплатишка и у скольких из них ноль байт. Если «нули» распределены как обычный отвал воронки —
проблема доставки не подтверждена и приоритет задачи падает.

### ⚠️ Чего это решение НЕ лечит (замер владельца, центр Москвы, 2026-07-28)

В центре Москвы **не работал и российский узел** «При белых списках» — владелец проверял именно его,
не литовский. На его районе тот же узел работает. Значит в центре либо фильтр жёстче SNI-маскировки,
либо мобильный интернет глушится полностью.

**Вывод: раздача конфигов текстом НЕ лечит центр Москвы.** Если до узла не доходят пакеты, наличие
конфига на руках ничего не меняет. Это решение лечит только случай «человек в обычных условиях не
смог скачать подписку». Насколько такой случай реален — покажет сверка с `vpn_subscriptions` выше.
Причина отказа в центре пока не измерена (нужен tcpdump на входе в момент попытки).

### Решение: слать конфиги текстом вместе со ссылкой

Бэкенд **сам** (server-side, у него интернет есть) скачивает подписку, раскодирует и отправляет юзеру
готовые строки `vless://` прямо в сообщение бота. Юзер копирует и вставляет в приложение —
никуда ходить не нужно, зарубежный IP не требуется.

Генерировать конфиги вручную НЕ надо: панель уже отдаёт их готовыми.

```ts
// Псевдокод для бэкенда Оплатишки
async function getVpnConfigs(subscriptionUrl: string): Promise<string[]> {
  const res = await fetch(subscriptionUrl, {
    headers: { 'user-agent': 'Happ/1.0' },   // любой НЕПУСТОЙ UA; с пустым придёт JSON 404
    signal: AbortSignal.timeout(10_000),
  })
  if (!res.ok) return []                      // мягкая деградация: отдадим только ссылку
  const body = (await res.text()).trim()

  // Тело может быть уже plain-text — Buffer.from(x,'base64') на нём НЕ бросит, вернёт мусор.
  const decoded = body.startsWith('vless://')
    ? body
    : Buffer.from(body, 'base64').toString('utf-8')

  return decoded
    .split('\n')
    .map(s => s.trim())
    .filter(s => s.startsWith('vless://'))    // валидация каждой строки, а не просто filter(Boolean)
}
```

### Как отправлять в боте

1. **Первым** — российский узел (`#🇷🇺 При белых списках`), с подписью «если в городе не работает
   интернет — подключайся через этот». Он для шатдаунов и белых списков.
2. **Вторым** — литовский (`#🇱🇹 Lithuania`), подпись «обычный, когда интернет работает нормально».
3. Каждую строку — **отдельным сообщением** в моноширинном блоке (`parse_mode: 'HTML'`, тег `<code>`),
   чтобы копировалось одним тапом.
4. Ссылку-подписку оставить как есть — она удобнее, когда интернет нормальный (сама обновляет список
   серверов). Конфиги текстом — страховка на случай, когда подписка недоступна.

### Требования и грабли

- **Строку не ломать.** Копируется целиком, от `vless://` до конца. Никаких переносов, пробелов,
  markdown-экранирования внутри. Не оборачивать в ссылку — Telegram испортит.
- **Метка после `#`** — это название сервера в списке приложения. Не удалять (иначе юзер не поймёт,
  какой из двух какой). Эмодзи и кириллица иногда бьются при копировании — при проблемах слать
  латиницей (`#RU`, `#LT`).
- **Конфиг — это credential**, содержит `vlessUuid` юзера. Слать только в личку владельцу аккаунта.
  **Не писать в БД, не логировать, не отправлять в Sentry** — тот же режим, что уже применён
  к ссылке-подписке (`vpn-flow.ts:131-139`, `subscriptionUrl: '[ссылка скрыта]'`).
- **`escapeHtml` обязателен.** В строке есть `&` (`?type=tcp&security=reality&…`). Без экранирования
  Telegram испортит конфиг внутри `<code>`. После реализации — вручную скопировать из сообщения
  и сверить байт в байт с тем, что отдала панель.
- **Мягкая деградация.** Сейчас повторное нажатие не ходит в панель, а отдаёт снимок из БД.
  Скачивание подписки добавляет внешний вызов: при таймауте/ошибке всё равно отдаём ссылку и
  скриншоты, а не роняем весь ответ.
- **Флуд-лимиты Telegram.** Альбом + 3 сообщения подряд — уже близко к границе. Либо слать оба
  конфига одним сообщением двумя блоками `<code>`, либо разнести по времени.
- **Не кэшировать надолго.** При ротации узлов конфиг меняется. Тянуть при нажатии кнопки либо
  кэшировать не дольше часа. Отзыв при этом безопасен: `revoke` ротирует `vlessUuid` (замер выше).
- Хорошее дополнение — **QR-код** из той же строки: Happ умеет сканировать, копипаст не нужен.

### Почему нельзя просто увести домен подписки на российский адрес

Предложение «поставить `sub.mxpkn8ns.ru` на московский VPS (Timeweb), и подписка продолжит сама
обновлять список серверов» выглядит системнее, но **на белых списках не сработает**.

Замер 2026-07-21 (MegaFon, живой РФ-телефон, 81 `accepted`): whitelist сверяет **SNI с владельцем IP**,
а не просто «российский IP». Проверенные комбинации:

| Вход | SNI | Результат |
|---|---|---|
| Beget (AS198610) | `vk.com` | ❌ не проходит |
| Yandex Cloud (AS200350) | `vk.com` | ❌ не проходит — белый IP сам по себе не спасает |
| Yandex Cloud (AS200350) | `ya.ru` | ✅ проходит |

Отсюда асимметрия: **VPN-соединение проходит потому, что Reality маскирует его под `ya.ru`** —
в ClientHello уходит яндексовый SNI на яндексовом IP. Обычный HTTPS-запрос за подпиской так
замаскировать нельзя: в нём будет реальный SNI `sub.mxpkn8ns.ru`, который белому списку чужой,
на каком бы российском адресе домен ни стоял.

Поэтому раздача конфигов текстом — не «убийство ценности подписки», а единственный путь доставки
там, где HTTPS до нашего домена не проходит. Подписка остаётся основным механизмом (и продолжает
обновлять список узлов при ротации), конфиги текстом идут как запасной путь для первого подключения.

⚠️ Оговорка: правило «SNI = владелец IP» снято на MegaFon 21.07 в одном районе. В центре Москвы
28.07 не прошёл и сам VPN-узел — там правило либо жёстче, либо интернет глушится целиком.
Не переносить этот вывод на всю РФ без нового замера.

## Схема БД (предложение — таблица `vpn_subscriptions`)

| поле                 | тип         | назначение                                  |
|----------------------|-------------|---------------------------------------------|
| `user_id`            | FK users    | владелец (юзер Оплатишки)                   |
| `telegram_id`        | bigint      | ТГ-id (ключ поиска в Remnawave)             |
| `remnawave_uuid`     | uuid        | `response.uuid` — для update/disable        |
| `subscription_url`   | text        | что отдали клиенту                          |
| `plan`               | text        | тариф/срок                                  |
| `status`             | text        | зеркало статуса панели                      |
| `expire_at`          | timestamptz | срок                                        |
| `created_at`/`updated_at` | timestamptz | аудит                                  |

Уникальность по `telegram_id` (или `remnawave_uuid`) — чтобы не плодить дубли.

## Как выпустить отдельный токен для Оплатишки

В панели: **Настройки Remnawave → API-токены (API Keys)** → создать новый токен «oplatishka-backend» → положить его в env бэкенда Оплатишки (`REMNAWAVE_API_TOKEN`), НЕ в мастер-токен владельца. Отзыв — там же.
(Мастер-токен владельца сейчас в `secrets/server-baseline/remnawave/api-token.env` этого репо — его агенту НЕ давать.)

## Грабли / примечания

- `response.uuid` (для операций) ≠ `response.vlessUuid` (id протокола). Храни `uuid`.
- Подписка per-user и стабильна (по `shortUuid`) — можно писать в БД один раз.
- Один `telegramId` = один юзер панели: перед созданием всегда проверяй `by-telegram-id`.
- Всё server-side. Токен — только в env бэкенда.
- Инфраструктура (ноды, whitelist, цепочка) уже готова и живёт в панели — бэкенду достаточно CRUD по юзерам.

**кнопка «🛡 VPN» в /start-меню бота (Remnawave, 2026-07-21).** Callback `vpn` выдаёт персональную ссылку-подписку из панели `panel.mxpkn8ns.ru` (клиент `lib/remnawave/`: Bearer `REMNAWAVE_API_TOKEN` — ТОЛЬКО server-side/env, timeout 10s, без ретраев; Zod-контракт `@oplati/types` подтверждён живыми вызовами 2026-07-21, справочник — [`docs/reference/remnawave-api.md`](docs/reference/remnawave-api.md)).
