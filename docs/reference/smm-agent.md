# SMM-бот канала @ooplatishka

Свой узкий бот вместо выведенного Hermes-агента Гилфойла (решение владельца
22.09.2026, разбор — `.scratch/smm-agent-choice/`, спека и тикеты —
`.scratch/smm-bot/`). Код — `apps/smm`, деплой — отдельное приложение Dokploy
`oplatishka-smm` на том же VPS во Франкфурте.

Прежний контур описан в [`../history/smm-agent-hermes.md`](../history/smm-agent-hermes.md)
(⚠️ описывает то, чего уже нет).

## Что делает

Бот пишет посты в @ooplatishka и готовит версии для Threads. Диалог с
владельцем — **кнопочный автомат**, а не свободный чат: модель пишет текст и
оценивает его, но НИКОГДА не решает, что происходит дальше.

Команды (из `src/bot/bot.ts`, там же список для `setMyCommands`):

| Команда | Что делает |
|---|---|
| `/post <ссылка или тема>` | новый пост в канал |
| `/threads <ссылка или тема>` | пост для Threads |
| `/ideas` | темы из источников с кнопками «Написать», «Пропустить», «Не по теме» |
| `/queue` | начатые черновики с кнопками «Показать» и «Снять» |
| `/stats` | отчёт за 30 дней: что вышло, рубрики, реклама, просмотры, расход |
| `/settings` | состояние; `digest on|off|<час МСК внутри окна опроса 9–21>` — ежедневный дайджест |
| `/cancel` | снять текущий пост |

Бот слушает ТОЛЬКО владельца (`SMM_OWNER_ID`). Чужое сообщение не получает
ответа вовсе: отвечать «вам сюда нельзя» — повод написать ещё раз.

## Конвейер поста

`источник → досье → план (рубрика + углы) → автор → линт → редактор → превью → публикация`

- **Источник** — ссылка (страница качается и разбирается) или тема (поиск
  Tavily, владелец выбирает первоисточник кнопкой). Про сам продукт
  «Оплатишка» бот не пишет: отказ выдаётся ДО сети и до модели.
- **Линт — код, а не модель**: длина раскладки, структура, стена текста,
  свежесть против последних постов, нейросетевые обороты, красные линии
  (⚠️ страна выпуска карты, гарантии и обещания возврата денег, названия
  провайдеров и инфраструктуры, CVC/CVV, идентификаторы чатов, отзывы,
  рублёвая цена и курс).
- **Редактор** — та же модель другой ролью (семь критериев у канала, восемь
  у Threads). Один круг правок по линту, до двух по редактору.
- **Превью = публикация**: владельцу приходит РОВНО то сообщение, которое уйдёт
  в канал, а кнопки — отдельным сообщением рядом.

## Инварианты

1. **Публикация только по кнопке владельца.** Гейт двойной: автомат пишет
   решение `approve` с отпечатком текста, исполнитель ПЕРЕД отправкой
   перечитывает право из базы (`isApprovedForPublish`: решение создано после
   показа превью, отпечаток совпадает с текущим телом, автор — владелец по
   telegram id). Правка тела механически снимает право.
2. **Превью — это факт.** От показа отсчитывается право на публикацию; правка
   после показа требует нового подтверждения.
3. **Линт идёт ДО судьи.** Платить модели за оценку текста, который не прошёл
   машинную проверку, незачем.
4. **Текст владельца уходит дословно.** Ни линт, ни редактор его не переписывают
   (линт считается только для отчёта владельцу).
5. **Одна модель на все роли** (`deepseek-flash`), судья той же семьи —
   **принятый риск**: модель склонна хвалить свой текст. Лечится не второй
   моделью, а калибровкой: `pnpm --filter smm eval:judge` сравнивает оценки
   вышедших и снятых постов, и если снятые оценивались не ниже — пороги держат
   не то.
6. **Публикует в Threads ЧЕЛОВЕК.** У площадки нет ни разметки, ни кнопок, ни
   публикации без App Review: бот готовит текст и отдаёт кнопку Web Intent,
   «Выложил» фиксирует факт.
7. **Текст чужого поста наружу не идёт.** Из источников берутся только адрес
   первоисточника и заголовок — ни в базе, ни в логе, ни в промпте чужого
   текста нет.

## Наблюдаемость

Сторож здоровья ходит по проверкам при старте и раз в час: бот (`getMe`),
**баланс модели** (меньше доллара — красно), ключ поиска, база, зависшая
очередь, публикация с истёкшим окном отмены. Красное уходит в тему «Ошибки»
ops-группы **от бота входа** (`OPS_BOT_TOKEN`) — правило ops-группы: один
отправитель у всех машинных сообщений. Дедуп шесть часов по набору причин,
выздоровление даёт одно «снова зелено».

Список проверок родился из инцидента 08.09.2026: счёт у провайдера модели ушёл
в минус посреди прогона, бот молча перестал писать посты, сигнала не было.

## Как откатить

Предыдущий образ в панели Dokploy: приложение `oplatishka-smm` → Deployments →
нужная сборка → Redeploy. База на томе переживает откат; миграции
forward-only, поэтому откат на образ СТАРШЕ применённой миграции требует того
же порядка, что у веба — [`../runbooks/rollback.md`](../runbooks/rollback.md).

Быстрее всего погасить бота, не откатывая: остановить приложение в Dokploy.
Посты в канале при этом не трогаются — бот их не удаляет.

## Грабли

- **Витрина канала отдаёт посты-ОТВЕТЫ так, что первым идёт цитата чужого
  поста.** Разбор берёт `js-message_text`, а не первый попавшийся блок текста:
  иначе читается чужой пост вместе с его ссылками и мимо меток рекламы
  (ревью 22.09.2026 на живых `meduzalive` и `tginfo`).
- **Ручка X отдаёт «100 самых популярных» твитов, а не последние.** Без
  отсечки по дате в ленту идей приезжает прошлогоднее.
- **Кредиты ScrapeCreators не возобновляются.** Платные источники
  опрашиваются раз в 12 часов, а не каждый прогон (семь прогонов в сутки).
- **Threads: параметр `url` в Web Intent теряется на Android** — ссылка идёт
  текстом в последний ответ цепочки.
- **Списки каналов, аккаунтов X, сабреддитов и запросов Threads пусты
  намеренно** — это редакторский выбор владельца. Ленты RSS заполнены тремя
  адресами, проверенными живым запросом.
- **`eval:live` публикует посты** — только в `SMM_EVAL_CHANNEL_ID`; совпадение
  с боевым каналом останавливает прогон.
- **⚠️ Watch paths в Dokploy у приложения ПУСТЫ намеренно.** Панель фильтрует
  вебхук по списку изменённых файлов из тела запроса, а `deploy.yml` шлёт
  только `{"ref": …}` — со списком путей Dokploy отвечает
  `301 {"message":"Watch Paths Not Match"}` и не собирает НИКОГДА (проверено
  живым вызовом 22.09.2026). Фильтр «правка бота не пересобирает прод» живёт в
  job `changes` пайплайна, а не в панели; два фильтра подряд означали бы
  молчаливое «сборка не запускалась».
